# 河道氨氮快照发布平台

面向河道水质数据管理员的浏览器应用：每周把实验室导出的 CSV 上传，平台校验后
将整份快照发布为新的「当前数据集」，所有结果统一换算为 **mg/L**，供趋势分析使用。

技术栈：FastAPI + SQLite（浏览器界面，Jinja2 模板），Docker Compose 启动。

## 快速开始

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

数据保存在名为 `water-data` 的 Docker 卷中（数据库、版本文件、审计日志），
容器重启或重建都不会丢失。端口可用 `APP_PORT` 覆盖：

```bash
APP_PORT=8080 docker compose up -d --build
```

停止：`docker compose down`（卷保留）。彻底清理：`docker compose down -v`。

## 使用流程

1. 在首页选择实验室 CSV 并提交。
2. 平台读取表头（支持中英文别名，如 `站点/station/site_id`、
   `采样时间/sample_time`、`结果/result/value`、`单位/unit`）。
3. 逐行校验站点、采样时间、结果、单位；把 μg/L 换算为 mg/L（精确十进制换算）。
4. **全部通过才整份发布**；任何一行有错或存在冲突则整份拒绝，页面列出具体行号与原因，
   旧版本保持为当前版本、继续可下载。
5. 发布成功后首页显示当前版本，点击「下载当前版 CSV」即可获取 mg/L 数据集。

CSV 示例：

```csv
站点,采样时间,结果,单位
闸口站,2026-11-02 08:00,0.42,mg/L
桥头站,2026-11-02 08:00,480,μg/L
```

下载文件包含 `站点, 采样时间, 结果(mg/L), 来源单位, 原始结果` 五列，
便于追溯换算来源。

## 关键规则

| 规则 | 行为 |
| --- | --- |
| 单位 | 仅接受 mg/L、μg/L（含 `mg/l`、`mg L-1`、`µg·L⁻¹`、`毫克/升` 等写法）；其它单位整份拒绝 |
| 时间 | 统一规范为 UTC `YYYY-MM-DD HH:MM:SS`；无时区的时间按 UTC 处理 |
| 同站同时间冲突 | 同一快照内同一站点同一采样时间换算后数值不一致 → 指出冲突并拒绝整份 |
| 同值重复行 | 换算后数值一致 → 自动合并，提示重复行 |
| 完整快照 | 新快照整体替换当前数据集；同键不同值属于修订，页面会提示新增/变化/移除条数 |
| 重复上传 | 字节相同或数据相同的文件不会创建新版本，返回上一版本号 |
| 失败处理 | 文件写入或数据库登记失败 → 事务回滚、清理未登记文件，旧版本仍可下载 |
| 下载一致性 | 每个版本是不可变文件，下载指向单一版本，绝不混入新旧内容 |

## 页面与接口

| 路径 | 说明 |
| --- | --- |
| `GET /` | 当前版本、上传表单、最近上传与版本 |
| `GET /versions` | 全部版本与上传审计 |
| `GET /versions/{n}` | 单个版本明细（SHA-256、记录分页） |
| `POST /upload` | 上传并发布（浏览器表单） |
| `GET /download/current` | 下载当前版本 CSV |
| `GET /download/{n}` | 下载指定版本 CSV |
| `GET /api/current` | 当前版本 JSON |
| `GET /healthz` | 健康检查（容器 HEALTHCHECK 使用） |

## 配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `WATER_DATA_DIR` | `./data`（镜像内 `/data`） | 数据目录（数据库、版本文件） |
| `WATER_DB_PATH` | `<数据目录>/app.db` | 单独指定数据库路径 |
| `WATER_MAX_UPLOAD_MB` | `10` | 单文件上限 |
| `WATER_MAX_ROWS` | `200000` | 单快照行数上限 |
| `APP_PORT` | `8000` | Compose 暴露端口 |

## 本地开发与测试

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
pytest
```

测试覆盖单位换算、表头别名、冲突检测、重复上传、文件/数据库故障注入、
并发上传去重，以及「发布过程中下载不混入新旧内容」等不变量。

## 实现要点

- **全有或全无**：写事务使用 `BEGIN IMMEDIATE`，在锁内重新检查重复上传、
  分配版本号、写入全部记录并更新当前版本指针，一次性提交。
- **不可变版本文件**：发布内容先写入 `staging/` 并 `fsync`，再原子重命名到
  `versions/vNNNN.csv`；文件一经发布不再修改，下载因此不存在新旧混合。
- **失败可恢复**：数据库登记失败时回滚事务并删除本次未登记文件；启动时把
  崩溃遗留的未登记文件移到 `orphans/`（保留数据，不直接删除）。
- **只读降级**：数据卷只读时页面与旧版本下载仍可用，发布失败会明确提示且不影响旧版本。
- **精确数值**：使用 `Decimal` 完成换算与冲突比较，避免浮点误差。
